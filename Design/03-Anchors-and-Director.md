# 03 · 锚点与 Intent 参与

锚点的定义（已确认）：

| 旧理解 | 新理解 |
|--------|--------|
| 锚点 = C# 固定剧情 | 锚点 = **GameSystem 的结构性承诺** |

保证「一定发生」的是结构；「她怎么看、怎么回应」优先交给 Voice + Intent。

---

## 三日锚点各自保证什么

| 锚点 | GameSystem 承诺 | 关系权限 |
|------|-----------------|----------|
| Day1 委托 | 一定出现并完成一次需要协作的委托 | 进入她的**事务** |
| Day2 共现 | 一定给玩家进入她生活轨道的机会 | 进入她的**生活** |
| Day3 偏离 | 一定发生一次合法的真轨道改变 | 请求**改变她的安排** |

---

## 何处应开 Intent（Director）

判定尺子：

> 若完全由 C# 写死，玩家会不会少一次看到「Remi 如何回应我」的机会？  
> 会 → 优先开 Intent；失败由 GameSystem fallback。

### Day1 · 委托

| 环节 | Intent？ | 说明 |
|------|----------|------|
| 窗口 / 保底时机 | 不必开 | GameSystem |
| 她如何提出找书 | **应开** | 意愿与提出方式 |
| 交书时如何看待玩家 | **应开** | 致谢态度 → 可约束 Voice |
| 黑屏 / 一瞥机位 | 不必开 | GameSystem |

### Day2 · 共现

| 环节 | Intent？ | 说明 |
|------|----------|------|
| 邀约必达 / Chip | 不必开 / 可开文案侧 | 结构必达归 GameSystem |
| 进馆 Anchor 开场态度 | **应开** | 见面如何看你 |
| FreeChat / Whisper | **应开** / 可开 | 表现与短答 |
| 巡逻路点 | 不必开 | GameSystem |
| 告别态度 | **应开** | 共现落点的关系感 |
| 过场日切 | 不必开 | GameSystem |

### Day3 · 偏离

| 环节 | Intent？ | 说明 |
|------|----------|------|
| 偏离窗口 Open/Close | 不必开 | GameSystem 状态 |
| 自由输入是否提偏离 | **应开**（独立 Intent：`RemiDeviationDetectIntent`） | 手机窗口期已接；失败当闲聊 |
| 是否愿意采纳 / stance | **应开**（可另一次 Intent） | 再喂 Voice |
| 保底：她主动递球 | **可开** → 长期应开 | 不伪造玩家发言 |
| Chip「那走吧」 | 不必开 | 确认交互 |
| 改日程 / 传公寓 | 不必开 | GameSystem 执行 |
| 公寓 intro 态度 | **应开** | 偏离后共在 |

### 刻意不必开 Intent

日历、beat、窗口计时、场景加载、传送、机位、巡逻数值、目标白名单校验、JSON 失败后的 fallback 路径本身。

---

## 落地优先级（原则，非排期）

1. Day3：DeviationDetect（独立 Intent）→ 合法则执行；保底仍留 GameSystem  
2. Day1：交书时的回应判断  
3. Day2：见面 / 告别态度  

工程提醒：现有 Intent 线多止于 `expression`；上表「应开」指**加宽 Intent 族的分次请求**，不是把一切塞进表情那一次调用。
